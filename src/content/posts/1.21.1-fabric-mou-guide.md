# 1.21.1 Fabric Mou 整合包完整使用指南

本文基于 2026 年 9 月 22 日的整合包实际 `mods/`、`config/`、`options.txt` 整理。文中的版本号、快捷键和启用状态均指这个实例快照，不代表模组官网的最新版本或全新安装时的默认设置。

整合包的核心逻辑可以分成六组：

1. **生电与建造**：Carpet 及其 TIS / REMS / Org 扩展、Litematica + Printer、MiniHUD、Tweakeroo、TweakerMore 等。
2. **物品与交互**：连锁操作、背包整理、Quick Shulker、附魔处理等。
3. **地图、信息与界面**：JourneyMap、Jade、JEI、进度界面、聊天增强、皮肤与局域网设置。
4. **录像与创作**：Flashback 游戏录像、回放与电影镜头导出。
5. **性能与渲染**：Sodium、Lithium、Iris、Ixeris、Super Resolution、ETF/EMF 等。
6. **前置与依赖库**：为其他模组提供接口和运行环境，本身通常不需要操作。

### 本次文件盘点结论

- `mods/` 中共有 69 个 `.jar`，每个都能读取到独立的 `fabric.mod.json`；另有 1 个加载器 JSON 文件不是模组。
- 没有发现重复的顶层 Mod ID。
- 潜影盒相关已从旧文的 Better Shulkers 换成 **Quick Shulker**；`config/bettershulkers.toml` 是历史残留，当前不生效。
- Carpet 生态从单一 GCA 扩展到 **GCA + Carpet TIS Addition + REMS Carpet Addition + Carpet Org Addition** 四件套。
- 新增录像模组 Flashback（约 200 MB），以及实体资源包兼容层 ETF + EMF。
- 当前实例可以进入游戏和世界，但 `Trade Cycling 1.0.20` 与 `Visible Traders 1.3.2` 的联动初始化失败，文章后面会给出影响范围和处理方式。

## 安装与首次启动

### 环境要求

- 使用 64 位 Java 21。
- 使用 Minecraft 1.21.1 对应的 Fabric Loader。
- 不要混入 Forge、NeoForge 或其他 Minecraft 版本的模组。
- 首次启动建议分配 4–6 GB 内存，使用大型资源包或光影时再按需增加。

### 首次启动流程

1. 启动游戏后打开 Mod Menu，确认模组列表正常。
2. 创建测试世界，不要立刻进入唯一的重要存档。
3. 检查 Sodium 视频设置、JourneyMap、JEI、Jade 和 Masa 系模组菜单。
4. 使用 Controlling 检查按键冲突。
5. 确认没有启动、渲染和按键异常后，再导入存档、原理图与地图数据。

### 重要目录

| 目录或文件 | 用途 | 建议 |
|---|---|---|
| `mods/` | 模组文件 | 更新前备份 |
| `config/` | 模组配置和快捷键 | 必须备份 |
| `saves/` | 单人世界 | 必须备份 |
| `schematics/` | Litematica 原理图 | 建议备份 |
| `journeymap/` | 地图和路径点 | 迁移实例时备份 |
| `shaderpacks/` | Iris 光影包 | 按需备份 |
| `resourcepacks/` | 资源包 | 按需备份 |
| `options.txt` | 语言、视频和原版按键 | 排错前备份 |
| `logs/latest.log` | 最近一次启动日志 | 出错时优先查看 |

## 推荐学习顺序

1. 先用 Controlling 处理按键冲突（尤其 F6、反引号、K、O、R）。
2. 学习 Litematica 的投影、材料列表和验证器，再按需上 Litematica Printer。
3. 学习 MiniHUD 的结构边界、刷怪范围和光照显示。
4. 学习 Tweakeroo 的自由相机与灵活放置，TweakerMore 作补充。
5. 在测试世界学习 Carpet 与 GCA / TIS / REMS / Org（规则默认关，逐个开）。
6. 配置 JourneyMap、JEI、Jade、Quick Shulker 和物品整理功能。
7. 要做演示片再学 Flashback；要开超分/实体资源包再动 Super Resolution 和 ETF/EMF。
8. 最后根据电脑性能决定是否开启 Iris 光影和动态光源。

### 已知冲突

- **M**：Litematica 前缀键，同时 JourneyMap 用于切换小地图；Litematica 组合键需要连续/组合输入，通常仍可使用。
- **O**：JEI 物品列表开关与 Iris 光影包选择冲突，建议修改 Iris 为 `Ctrl + O`。
- **R**：JEI 查看配方与 Iris 重载光影冲突，建议修改 Iris 为 `Ctrl + R`。
- **K**：Iris 光影开关与 Modern UI 配置中心冲突，建议把 Modern UI 改为 `Shift + K`，保留 Iris 的快速开关。
- **\**：JourneyMap 小地图预设与 Tweakeroo 工具切换存在冲突。
- **C**：Trade Cycling 与部分模组默认配置入口可能冲突。
- **F6**：Zoomify 备用缩放键与 Super Resolution 配置键冲突，建议给 Super Resolution 换键。
- **`（反引号）**：FTB Ultimine 与 Litematica Printer 开关组合键共用反引号，注意 Caps Lock 状态。
- **左 Alt**：Litematica、MiniHUD、Tweakeroo 多处作为修饰键，操作前确认当前工具模式。

### 建议的未绑定功能

- EntityCulling 开关：建议绑定仅用于排错的组合键。
- LambDynamicLights 开关：建议绑定，刷怪测试前快速关闭。
- Neat 血条开关：建议绑定，截图和大型实体农场时关闭。
- Dynamic FPS 强制/禁用：一般保持未绑定即可。
- Flashback 标记 1–4：录像剪辑需要章节点时再绑定。
- Super Resolution 配置：与 Zoomify 冲突，建议改绑。

### Carpet Mod（地毯）

**快捷键**

> 该模组没有需要玩家操作的快捷键，或当前没有绑定快捷键。

**快速入门**

**假人教程**
- 生成假人：`/player Bot spawn`

- 停止动作：`/player Bot stop`
- 下线：`/player Bot kill`

**生电常用方法**
1. 用假人测试刷怪塔挂机位、村民繁殖、农场收集和区块加载边界。
2. 修改规则前先用 `/carpet <规则名>` 阅读说明，避免把测试规则永久写入主世界。
3. 世界级规则保存在存档目录的 `carpet.conf`；整合包默认规则位于 `config/carpet/default_carpet.conf`。
4. 使用 `/log` 订阅 TPS、mobcaps 等记录器时，可在聊天栏持续观察服务器状态。

**推荐与注意事项**

- 主世界只永久保存明确需要的规则，临时测试结束后恢复默认。

**依赖关系**

### Litematica Printer（打印机）

**快捷键**

| 功能 | 当前快捷键 |
|---|---|
| 启用/禁用自动打印 | Caps Lock + `（反引号） |

**怎么用**

1. 先用 Litematica 放好原理图并进入 Easy Place / 放置管理状态。

### Trade Cycling（村民交易刷新）

> 在村民尚未锁定交易时，用快捷键快速重置工作站并刷新交易。

- **模组 ID**：`trade_cycling`
- **当前版本**：`1.21.1-1.0.20`
- **运行环境**：客户端与服务端/通用


**快捷键**

| 功能 | 当前快捷键 |
|---|---|
| 刷新交易 | C |

**使用步骤**
1. 放置村民对应工作站，让村民获得职业。
2. 打开交易界面并查看第一轮交易。
3. 在尚未与该村民完成任何交易时按 `C`。
4. 模组会尝试重置工作站并让村民重新获取职业，随后生成新交易。
5. 出现目标交易后完成一次交易，将职业和交易锁定。

**建筑党用途**
可快速获得修补、精准采集、效率等附魔书，以及石匠提供的石英、砖块和装饰材料交易。

**推荐与注意事项**

- 只对尚未锁定交易的村民有效。
- 确保工作站可被正常破坏、重新放置且村民能寻路绑定。
- 多人服务器必须允许对应行为。
- 当前 `latest.log` 显示它与 Visible Traders 的兼容层发生 `NoSuchMethodException`。基础刷新功能和“显示后续交易”应分别测试，不要默认两者联动正常。

### Visible Traders（可见村民交易）

> 提前显示村民尚未解锁的后续交易，减少为了确认高等级交易而反复培养村民的试错成本。

- **模组 ID**：`visibletraders`
- **当前版本**：`1.3.2`
- **运行环境**：客户端与服务端/通用

**快捷键**

> 没有独立快捷键，功能直接集成在村民交易界面中。

**从零开始**

1. 给未就业村民放置工作站，让它获得职业。
2. 右键村民打开交易界面。
3. 正常可交易的项目仍然显示在前面；尚未解锁的职业等级交易会提前展示。
4. 如果某项显示“正在生成”，等待服务器完成该村民的交易生成后再查看。
5. 根据后续交易是否符合需求，决定继续升级村民，或在尚未交易时更换工作站。

**与 Trade Cycling 配合**

理论上可以先查看交易，再用 Trade Cycling 刷新未锁定村民。但当前实例中 Trade Cycling 的 Visible Traders 兼容层找不到 1.3.2 提供的方法，因此联动初始化失败。实际使用时按下面顺序排查：

1. 单独打开交易界面，确认 Visible Traders 能否显示后续交易。
2. 再按 `C` 测试 Trade Cycling 的基础刷新。
3. 如果出现界面不同步、交易不刷新或日志持续报错，改用相互兼容的版本组合，或暂时只保留其中一个。
4. 不要在唯一的重要村民交易厅中直接测试版本更换。

**推荐与注意事项**

- 它不会替代正常的村民升级流程，只是提前显示后续交易。
- 多人服务器需要服务端支持，客户端单独安装不能保证拿到未生成的交易数据。
- 当前整合包应把它标记为“已安装，但与 Trade Cycling 联动异常”。

**依赖关系**

- `fabric-api`：`>=0.116.7+1.21.1`
- Java：`>=21`

**配置与数据位置**

- 当前版本没有需要普通玩家维护的独立配置文件。

**官方资料**

- [项目主页或官方文档](https://modrinth.com/mod/visibletraders)

- **模组 ID**：`inventoryprofilesnext`
- **当前版本**：`2.2.6`
- **运行环境**：仅客户端


**快捷键**

> 该模组没有需要玩家操作的快捷键，或当前没有绑定快捷键。

**快速开始**
打开物品栏或箱子后，界面边缘会出现排序按钮。可分别按名称、数量或类别整理玩家背包和容器。第一次使用先在设置中确认按钮位置，避免与 JEI/Jade 界面重叠。

**自定义规则**
规则文件位于配置目录，可用物品 ID、标签和通配符定义排序优先级。修改后先用普通箱子测试。

**推荐与注意事项**

- 不要对复杂分类仓库无脑点击双向移动按钮。
- 服务器延迟高时减少连续排序操作。
- 当前配置的 Profiles 和 Auto Refill 功能处于关闭状态，可按需开启。

### Continuity（连接纹理）

> 在 Fabric 环境中支持 OptiFine 风格的连接纹理、发光纹理和自定义方块渲染层。

- **模组 ID**：`continuity`
- **当前版本**：`3.0.0+1.21`
- **运行环境**：仅客户端

**快捷键**

> 没有独立快捷键，通过资源包页面和 Mod Menu 配置。

### More Culling（更多剔除）

> 优化方块面、云、雨雪、告示牌文字、展示框、画和树叶等渲染；与 EntityCulling 的作用范围不同。

- **模组 ID**：`moreculling`
- **当前版本**：`1.0.9`
- **运行环境**：仅客户端

**快捷键**

> 没有独立快捷键。当前配置会把 More Culling 选项加入 Sodium 视频设置，也可以从 Mod Menu 打开。

**从零开始**

1. 打开“选项 → 视频设置”，寻找 More Culling 分类；找不到时从 Mod Menu 进入配置。
2. 保持默认值进入普通世界，观察树叶、告示牌、展示框、地图墙、信标和雨雪。
3. 再到大型仓库、地图墙或森林区域比较帧率。
4. 如果出现物品展示框、树叶或模组方块缺面，只关闭对应项目，不要一次关闭全部剔除。

**当前实例已启用**

- BlockState Culling
- 自定义展示框渲染器
- 展示框地图剔除和 LOD，LOD 距离为 `16`

## 更新整合包

1. 备份 `mods/`、`config/`、`saves/`、`schematics/` 和 JourneyMap 数据。
2. 一次只更新一组关联模组，例如 Sodium 与 Iris，或 Litematica、MiniHUD、Tweakeroo 与 MaLiLib。
3. 删除旧版本，不要同时保留两个相同 Mod ID 的 JAR。
4. 首次启动后查看 `logs/latest.log`，确认没有依赖和版本错误。
5. 在测试世界验证后，再打开重要存档。

> [!WARNING]
> 不要在没有备份的情况下，用新模组版本直接打开唯一存档。移除添加物品、装备槽或持久化数据的模组可能造成内容丢失。

## 当前实例已知问题

以下内容来自 2026 年 8–9 月的实例状态与历史日志，不是泛用结论：

1. **Trade Cycling 与 Visible Traders 联动失败**
   Trade Cycling 1.0.20 反射调用 Visible Traders 1.3.2 的方法时出现 `NoSuchMethodException`。建议更换为互相兼容的版本组合，或暂时只保留一个；更换前先在测试世界验证村民交易。

2. **JER 初始化存在错误**
   日志中出现缺少 `config/jeresources.json` 和 JEI 插件错误。若 JER 的矿物分布、战利品或生物掉落标签为空，先生成或重置 JER 配置，再测试与当前 JEI 版本的兼容性。

3. **部分优化模组存在 Mixin 覆盖提示**
   ModernFix 与 Lithium、Carpet 与 Architectury、Litematica/Tweakeroo、Iris/Tweakeroo 之间出现覆盖或优先级警告。游戏目前能够进入世界，但涉及结构方块范围、Easy Place、视角晃动或温度缓存时应单独测试。

4. **资源包包含无效路径或帧索引**
   `PBSO1.21.1.zip` 和 `XKRD 红显` 资源包产生路径、方块状态或动画帧警告。遇到纹理缺失和动画异常时，先禁用这两个资源包复现。

5. **Quick Shulker 与 Better Shulkers 配置残留**
   已改用 Quick Shulker，但 `config/bettershulkers.toml` 仍在。它不会生效，可删除；不要按旧文的 `/shulker set` 流程操作。

6. **Super Resolution 处于 alpha**
   `0.9.1-alpha.1+opengl` 可能与光影、UI 缩放冲突；默认当实验特性，异常先关它。

7. **Litematica Printer 默认未启用**
   `workingSwitch.enabled=false`，需要手动开；联机环境多半违规，进服先问规则。

8. **Zoomify 与 Super Resolution 键位冲突**
   两者都占 `F6`。建议给 Super Resolution 改绑。

## 通用排错流程

### 启动提示缺少依赖

启动错误通常会写出缺少的 Mod ID 和版本范围。按照日志提示补齐依赖，不要只根据 JAR 文件名猜测。

### 快捷键没有反应

1. 使用 Controlling 搜索功能名称。
2. 检查功能是否未绑定或存在冲突。
3. 检查 Masa 系模组总开关是否关闭。
4. 确认组合键的前缀键和触发顺序。
5. 确认服务器是否安装对应模组或允许该功能。

### 画面、HUD 或实体显示异常

依次测试：资源包 → Iris 和光影 → Sodium → EntityCulling → MiniHUD、Jade、Neat → 动态光源。每次只改变一个变量，才能定位真正原因。

### 存档无法进入

- 先复制存档，再开始排错。
- 查看日志中最早出现的异常，而不只是最后一行。
- 检查最近是否移除了添加方块、物品、装备槽或数据组件的模组。
- 恢复最近一次可用的模组和配置组合后再测试。

### 语言列表为空

如果 `options.txt` 已设置 `lang:zh_cn`，但语言列表仍完全为空，通常是共享资源没有下载完整。

1. 完全关闭游戏。
2. 使用启动器的“检查文件”“补全文件”或“重新下载资源”。
3. 确认启动器检查了共享的 `.minecraft/assets/`，而不是只下载版本 JAR。
4. 重点检查 `assets/indexes/` 和 `assets/objects/`。
5. 补全资源后重新启动。

### 语言或按键无法保存

查看 `logs/latest.log` 是否出现 `Error saving option`。常见原因包括配置文件只读、目录没有写入权限、模组持续覆盖选项，或 Gamma、亮度值超出原版允许范围。

必要时先备份 `options.txt`，再让游戏重新生成。

## 性能调节建议

1. 降低渲染距离和模拟距离。
2. 关闭不需要的 MiniHUD 覆盖层、实体血条和动态光源。
3. 施工和生电测试时关闭光影。
4. 减少 JourneyMap 的高频地图更新。
5. 降低光影的阴影距离、体积效果、反射和抗锯齿。
6. 检查是否同时加载多个大型资源包。
7. 分别观察客户端 FPS、服务端 MSPT、实体数量和内存占用。

## 最后

这套整合包的重点不是单纯增加模组数量，而是把投影施工、生电调试、材料管理、地图记录、录像创作和性能优化连接成完整工作流。

第一次使用时不要同时打开所有功能。先处理快捷键冲突，再逐步学习 Litematica、MiniHUD 和 Tweakeroo，Carpet 扩展规则按需开启，Flashback 和超分放到最后，再根据电脑性能决定是否启用光影与动态效果。
