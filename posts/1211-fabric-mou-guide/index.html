1.21.1 Fabric Mou 整合包完整使用指南#

一篇文章看懂整合包内 47 个模组的定位、操作方式、快捷键、配置位置、依赖关系与注意事项。

本文基于整合包当前实际文件和配置整理。文中的版本号与快捷键均指整合包内配置，不代表模组的最新版本或默认设置。

下载整合包#

下载 Mou 0.1.0（GitHub Release）

  • Minecraft：1.21.1
  • Fabric Loader：0.19.3
  • 文件大小：约 120 MiB
  • SHA-256：2785A0372B7B203CAF6A887C1FC28B4230B70D116A5EE8D98F4D7F07902D72A1

下载后可以使用 PCL 直接导入压缩包，也可以从压缩包中的 .mrpack 文件导入到支持 Modrinth 整合包格式的启动器。首次启动前请确认启动器使用 Java 21。

IMPORTANT

投影、自由相机、灵活放置、连锁操作和 Carpet 规则可能受到服务器规则限制。进入多人服务器前，请先确认允许使用的功能范围。

整合包基本信息#

主要用途生电调试、投影施工、建筑辅助、地图记录、物品管理、性能优化

整合包的核心逻辑可以分成五组：

  1. 生电与建造：Carpet、Litematica、MiniHUD、Tweakeroo 等。
  2. 物品与交互：连锁操作、背包整理、潜影盒预览、附魔处理等。
  3. 地图、信息与界面：JourneyMap、Jade、JEI、按键管理与皮肤加载。
  4. 性能与渲染：Sodium、Lithium、Iris、ModernFix 等。
  5. 前置与依赖库：为其他模组提供接口和运行环境，本身通常不需要操作。

安装与首次启动#

环境要求#

  • 使用 64 位 Java 21。
  • 使用 Minecraft 1.21.1 对应的 Fabric Loader。
  • 不要混入 Forge、NeoForge 或其他 Minecraft 版本的模组。
  • 首次启动建议分配 4–6 GB 内存，使用大型资源包或光影时再按需增加。

首次启动流程#

  1. 启动游戏后打开 Mod Menu，确认模组列表正常。
  2. 创建测试世界，不要立刻进入唯一的重要存档。
  3. 检查 Sodium 视频设置、JourneyMap、JEI、Jade 和 Masa 系模组菜单。
  4. 使用 Controlling 检查按键冲突。
  5. 确认没有启动、渲染和按键异常后，再导入存档、原理图与地图数据。

推荐学习顺序#

  1. 先用 Controlling 处理按键冲突。
  2. 学习 Litematica 的投影、材料列表和验证器。
  3. 学习 MiniHUD 的结构边界、刷怪范围和光照显示。
  4. 学习 Tweakeroo 的自由相机与灵活放置。
  5. 在测试世界学习 Carpet 与 GCA。
  6. 配置 JourneyMap、JEI、Jade 和物品整理功能。
  7. 最后根据电脑性能决定是否开启 Iris 光影和动态光源。

已知冲突#

  • M：Litematica 前缀键，同时 JourneyMap 用于切换小地图；Litematica 组合键需要连续/组合输入，通常仍可使用。
  • O：JEI 物品列表开关与 Iris 光影包选择冲突，建议修改 Iris 为 Ctrl + O。
  • R：JEI 查看配方与 Iris 重载光影冲突，建议修改 Iris 为 Ctrl + R。
  • ****：JourneyMap 小地图预设与 Tweakeroo 工具切换存在冲突。
  • C：Trade Cycling 与部分模组默认配置入口可能冲突。
  • 左 Alt：Litematica、MiniHUD、Tweakeroo 多处作为修饰键，操作前确认当前工具模式。

建议的未绑定功能#

  • EntityCulling 开关：建议绑定仅用于排错的组合键。
  • LambDynamicLights 开关：建议绑定，刷怪测试前快速关闭。
  • Neat 血条开关：建议绑定，截图和大型实体农场时关闭。
  • Dynamic FPS 强制/禁用：一般保持未绑定即可。

全部模组使用教程#

下面按整合包分类逐个介绍全部 47 个模组。前置库也会说明是否能删除、由哪些模组使用以及排错时应该检查什么。

生电与建造#

投影施工、生电调试、自由相机、灵活放置和村民交易工具。

Carpet Mod（地毯）#

生电整合包的规则控制、假人测试和调试核心。

  • 模组 ID：carpet
  • 当前版本：1.4.147+v240613
  • 运行环境：客户端与服务端/通用

快捷键

该模组没有需要玩家操作的快捷键，或当前没有绑定快捷键。

快速入门 进入有权限的单人世界后，在聊天框输入 /carpet 查看规则。使用 /carpet <规则名> 查看说明，使用 /carpet <规则名> <值> 临时修改规则；追加 setDefault 可把规则写入当前世界配置。

假人教程

  • 生成假人：/player Bot spawn
  • 让假人站到指定位置：先站好位置和朝向，再生成同名假人。
  • 攻击：/player Bot attack continuous
  • 持续使用物品：/player Bot use continuous
  • 停止动作：/player Bot stop
  • 下线：/player Bot kill
  • 移动、跳跃、潜行、转向可通过 /player Bot move ...、jump、sneak、look 子命令组合。

生电常用方法

  1. 用假人测试刷怪塔挂机位、村民繁殖、农场收集和区块加载边界。
  2. 修改规则前先用 /carpet <规则名> 阅读说明，避免把测试规则永久写入主世界。
  3. 世界级规则保存在存档目录的 carpet.conf；整合包默认规则位于 config/carpet/default_carpet.conf。
  4. 使用 /log 订阅 TPS、mobcaps 等记录器时，可在聊天栏持续观察服务器状态。

推荐与注意事项

  • 主世界只永久保存明确需要的规则，临时测试结束后恢复默认。
  • 假人名称不要与真实玩家重名。
  • 结构方块范围功能与 Tweakeroo 有冲突时，以 Carpet 规则结果为准。

依赖关系

  • 无额外模组依赖，或依赖已打包在模组内部。

配置与数据位置

  • config/carpet/default_carpet.conf

Gugle Carpet Addition（GCA）#

围绕 Carpet 扩展的生电规则、假人交互和实用功能集合。

  • 模组 ID：gca_wrapper
  • 当前版本：2.12.6+build.94
  • 运行环境：客户端与服务端/通用

快捷键

该模组没有需要玩家操作的快捷键，或当前没有绑定快捷键。

使用方式 GCA 通过 Carpet 规则系统工作。输入 /carpet 后搜索带有 GCA 分类或前缀的规则；输入 /carpet <规则名> 查看该版本内置说明。

推荐流程

  1. 新建测试世界，先确认规则作用和默认值。
  2. 用 /carpet <规则名> <值> 临时启用。
  3. 验证机器不会被规则改变后，再决定是否写入世界默认配置。
  4. 配合 Carpet 假人完成挂机、自动操作、容器交互和农场压力测试。

为什么不列死全部规则 GCA 的规则会随构建版本调整，教程以游戏内 /carpet 自动补全和说明为准，避免博客中的旧规则名称误导玩家。

推荐与注意事项

  • 它不是独立替代品，必须与 Carpet 一起使用。
  • 升级 GCA 后先在测试世界检查旧规则。
  • 服务器使用时应由服主统一管理规则。

依赖关系

  • 无额外模组依赖，或依赖已打包在模组内部。

配置与数据位置

  • 世界目录/carpet.conf
  • config/carpet/default_carpet.conf

制作原理图

  1. 按 M 打开主菜单，在区域选择中创建选区。
  2. 手持木棍作为选择工具：左键设置角点 1，右键设置角点 2，中键选择已有元素。
  3. 检查选区尺寸和包含范围。
  4. 使用 Ctrl + Alt + S 保存为原理图文件。

加载与放置

  1. M → 加载原理图 选择文件。
  2. 创建放置后按 M + P 打开放置管理。
  3. 调整坐标、旋转、镜像和子区域开关。
  4. 按 M + G 控制投影显示，按 M + R 控制全部渲染。

生存施工

  • M + L 打开材料列表，查看总需求、缺少数量和已完成数量。
  • 使用逐层模式配合 Page Up/Page Down，适合从下到上施工。
  • 简单放置需要服务器或 Carpet 支持准确放置协议；不支持时仍可把投影视作普通施工参考。
  • M + V 打开验证器，检查错误方块、缺失方块和多余方块。

文件位置 原理图通常保存在实例的 schematics 目录。发布整合包时不要未经授权分发他人的建筑原理图。

推荐与注意事项

  • 大型投影先关闭不需要的子区域，显著降低渲染压力。
  • 先确认原点与旋转方向，再开始收集材料。
  • Easy Place 不是服务器权限绕过工具。

  • 模组 ID：inventoryprofilesnext
  • 当前版本：2.2.6
  • 运行环境：仅客户端

快捷键

该模组没有需要玩家操作的快捷键，或当前没有绑定快捷键。

快速开始 打开物品栏或箱子后，界面边缘会出现排序按钮。可分别按名称、数量或类别整理玩家背包和容器。第一次使用先在设置中确认按钮位置，避免与 JEI/Jade 界面重叠。

自定义规则 规则文件位于配置目录，可用物品 ID、标签和通配符定义排序优先级。修改后先用普通箱子测试。

  1. 在游戏中按句号快速创建当前位置路径点。

更新整合包#

  1. 备份 mods/、config/、saves/、schematics/ 和 JourneyMap 数据。
  2. 一次只更新一组关联模组，例如 Sodium 与 Iris，或 Litematica、MiniHUD、Tweakeroo 与 MaLiLib。
  3. 删除旧版本，不要同时保留两个相同 Mod ID 的 JAR。
  4. 首次启动后查看 logs/latest.log，确认没有依赖和版本错误。
  5. 在测试世界验证后，再打开重要存档。
WARNING

不要在没有备份的情况下，用新模组版本直接打开唯一存档。移除添加物品、装备槽或持久化数据的模组可能造成内容丢失。

启动提示缺少依赖#

启动错误通常会写出缺少的 Mod ID 和版本范围。按照日志提示补齐依赖，不要只根据 JAR 文件名猜测。

快捷键没有反应#

  1. 使用 Controlling 搜索功能名称。
  2. 检查功能是否未绑定或存在冲突。
  3. 检查 Masa 系模组总开关是否关闭。
  4. 确认组合键的前缀键和触发顺序。
  5. 确认服务器是否安装对应模组或允许该功能。

画面、HUD 或实体显示异常#

依次测试：资源包 → Iris 和光影 → Sodium → EntityCulling → MiniHUD、Jade、Neat → 动态光源。每次只改变一个变量，才能定位真正原因。

存档无法进入#

  • 先复制存档，再开始排错。
  • 查看日志中最早出现的异常，而不只是最后一行。
  • 检查最近是否移除了添加方块、物品、装备槽或数据组件的模组。
  • 恢复最近一次可用的模组和配置组合后再测试。

语言列表为空#

如果 options.txt 已设置 lang:zh_cn，但语言列表仍完全为空，通常是共享资源没有下载完整。

  1. 完全关闭游戏。
  2. 使用启动器的“检查文件”“补全文件”或“重新下载资源”。
  3. 确认启动器检查了共享的 .minecraft/assets/，而不是只下载版本 JAR。
  4. 重点检查 assets/indexes/ 和 assets/objects/。
  5. 补全资源后重新启动。

语言或按键无法保存#

查看 logs/latest.log 是否出现 Error saving option。常见原因包括配置文件只读、目录没有写入权限、模组持续覆盖选项，或 Gamma、亮度值超出原版允许范围。

必要时先备份 options.txt，再让游戏重新生成。

性能调节建议#

  1. 降低渲染距离和模拟距离。
  2. 关闭不需要的 MiniHUD 覆盖层、实体血条和动态光源。
  3. 施工和生电测试时关闭光影。
  4. 减少 JourneyMap 的高频地图更新。
  5. 降低光影的阴影距离、体积效果、反射和抗锯齿。
  6. 检查是否同时加载多个大型资源包。
  7. 分别观察客户端 FPS、服务端 MSPT、实体数量和内存占用。

最后#

这套整合包的重点不是单纯增加模组数量，而是把投影施工、生电调试、材料管理、地图记录和性能优化连接成完整工作流。

第一次使用时不要同时打开所有功能。先处理快捷键冲突，再逐步学习 Litematica、MiniHUD 和 Tweakeroo，最后根据电脑性能决定是否启用光影与动态效果。
